Worktree GC deletes the worktree of a running agent

smetana/src-tauri/src/worktree/gc.rs:142
Defect
collect_stale decides staleness from the mtime of the worktree root, which does not change when an agent writes only into nested directories.
Fails when
An agent edits wt/bd-a1b2/src/** for 31 minutes without touching the root → GC sees root mtime older than 30m → remove_dir_all("wt/bd-a1b2") runs under the live agent, uncommitted work is lost and the agent exits with ENOENT.
Fix
Before removal, read .smetana/agent.lock and skip the worktree if the holder PID is alive; fall back to mtime only when no lock exists.

▲ S1

Write-lock is not released when the agent task panics

smetana/src-tauri/src/agent/supervisor.rs:88
Defect
The lock is released by an explicit unlock() call at the end of run_agent, which is skipped on panic.
Fails when
The agent's tool call panics on a malformed diff → the task unwinds past unlock() → the task stays read-only with "Read-only while an agent is working." until the app restarts.
Fix
Return a LockGuard from lock() and release in its Drop impl.
▲ S2

Status hash differs between Rust and the UI for non-ASCII names

smetana/app/src/status/hash.ts:21
Defect
The UI runs FNV-1a over UTF-16 code units, while status.rs hashes UTF-8 bytes.
Fails when
A user status "ревью" → Rust slot 7, UI slot 2 → the tray badge and the board column show the same status in two different colours.
Fix
Hash new TextEncoder().encode(name) in the UI and add a shared fixture of 15 names checked by both test suites.
▲ S3

Migration fails when run a second time

bd-sync/crates/bd-sync-store/src/migrations/2026_10_14_000003_add_spawned_from_relation_index_to_tasks_table.rs:31
Defect
The index is created without IF NOT EXISTS, and the migration is not recorded until after the statement succeeds.
Fails when
The app is killed between CREATE INDEX and the migration-table insert → next launch reruns the migration → index idx_tasks_spawned_from already exists, the store refuses to open.
Fix
Use CREATE INDEX IF NOT EXISTS and wrap the statement and the migration record in one transaction.
